# Orion

一個關於「你的瀏覽器正在告訴這個網頁什麼」的中文教育性網站。

## 這是什麼

每次打開一個網頁，瀏覽器其實已經主動交出了不少資訊——裝置規格、螢幕解析度、時區、甚至連你有沒有在看這個分頁，都可以被讀取到。這些能力大多來自標準的瀏覽器 API，不需要特殊權限、也不需要你同意，單純是網頁技術原本就設計成這樣。

Orion 把這些資訊攤開來給你看，並用中文解釋每一項「這是什麼」「為什麼網站拿得到」。市面上同類型的工具（如 amiunique.org、browserleaks.com）多半只有英文介面，Orion 希望填上這塊中文資源的空缺。

## 為什麼做這個

瀏覽器的能耐，往往只有開發者才真正領悟。一般使用者把電腦當工具，有些玩家甚至只把特定程式當作某個遊戲或服務的啟動裝置，很少意識到瀏覽器本身就是一個能做很多事的環境——GitHub 上甚至有人純用 CSS 模擬 CPU 運作，證明光是 HTML、CSS、JS 這三樣，潛力就遠超過一般人的想像。這些能力不需要深奧的後端知識，只要你的電腦裝了瀏覽器，你就已經擁有一個能讀取、能執行這些技術的環境。

Orion 用最基礎的 JavaScript API（像 `navigator`）向使用者展示：光是打開一個網頁，開發者可能拿到哪些資訊。這些資訊可以被回傳給伺服器，成為使用者數據分析的一部分——這不必然是壞事，但使用者至少該知道這件事正在發生。

這個專案希望協助的，是讓一般使用者具備「什麼時候該緊張、該緊張什麼」（when and what to panic）的判斷力：即使只是誤觸一個網址、沒有點擊任何按鈕或連結，也可能已經洩漏了這些資訊。知道具體洩漏了什麼，才有辦法對應處理——在 AI 已經普及的時代，這也讓人更容易用精準的問題去問 AI「這樣會怎樣、我該怎麼辦」。而中文介面，或許也是這個網站相對同類工具的一點獨特之處。

## 內容涵蓋

- **基本瀏覽器資訊**：裝置、語言、螢幕、連線狀態、時區等，來自標準的 Navigator / Screen API
- **進階與指紋辨識資訊**：包含 Canvas Fingerprinting 這類較少被一般使用者意識到、卻被廣泛用於裝置識別的技術

每一項資訊都搭配中文說明，滑鼠移過去（hover）即可看到這項資訊是什麼、為什麼網站拿得到。

## 技術棧

- React + TypeScript
- Vite
- 純前端、無後端，所有資訊都是瀏覽器本機可直接讀取的內容

## 開發說明：AI 協作模式

這個專案的程式碼主要由 Claude 實作，但規劃、架構決策與提示詞設計由作者（Hambin）主導。這裡誠實記錄這個協作關係的實際樣貌，而不是用「貢獻者」這種暗示多人共同 commit 的格式來帶過。

**作者在這個專案中決定的部分：**
- 資料層與呈現層分離的整體架構（延續自作者過去專案的經驗，非 AI 提議）
- 何時該寫 TypeScript interface、何時該先讓資料長出來再回頭定義型別
- 資料分類邏輯採用「主題」（裝置／語言／螢幕……）而非「檔案來源」
- 視覺風格的取捨標準——例如明確要求「只取色票邏輯，不照抄介面」
- 功能發想（指紋辨識教育內容、歷史比對功能、裝置效能自適應動畫等）

**AI 實際負責的部分：**
- 依據上述決策落地的程式碼實作
- 語法層級的建議與除錯
- 在作者給定方向後，提出具體的技術選項供作者判斷

這個分工的實際效果：如果沒有作者預先定好架構原則，單靠 AI 生成，大概率會做出技術上能動、但缺乏分層、資料寫死在元件裡的版本。反過來說，作者目前仍在獨立建構 C# 的過程，前端的實作速度交給 AI 處理，讓作者能把心力留在規劃判斷與另一條學習主線上——這是一個關於怎麼分配有限心力的務實選擇，不是能力的全有或全無。

UI/UX 的實際體感調整（間距、字重、互動回饋是否「對」）則保留給作者本人判斷，這部分目前還是交給活人比較可靠。
